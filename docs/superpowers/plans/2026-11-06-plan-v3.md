# Plan cards v3 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Haiku only judges whether the current step is done (yes/no with evidence); code owns the time (factor ≥ 1, overdue growth, backoff); checks are event-driven; finished runs remember their steps' planned and real times.

**Architecture:** Pure logic and the three Haiku prompts in `plugins/tool-fold/hooks/plan.tsx`; wiring in `hooks/agents.tsx` (`checkPlan`, `replanPending`, `startPlan`, run end), narration capture in `hooks/register.tsx` (`session.append`), memory in `hooks/estimates.tsx` and `types/index.d.ts`.

**Tech Stack:** TypeScript/TSX mod hooks, `claude-code/testing`.

**Spec:** `docs/superpowers/specs/2026-11-06-plan-v3-design.md`

## Global Constraints

- `PLAN_ENABLED` / `REPLAN_ENABLED` stay the switches; non-plan cards unchanged.
- Percent never goes back (`anchor`); stale answers dropped by `seq` (and `done` for replans).
- `FACTOR_MIN` = 1, `FACTOR_MAX` = 3. Overdue growth: `max(60_000, 0.5 × (elapsed − stepAt))`. Overdue gaps: 30 s, 60 s, 120 s, 240 s (index = overdue checks so far, capped at 3). Event gap 60 s; ceiling 5 min.
- Plan build `maxTokens` 400; check `maxTokens` 120; replan 400; all Haiku, `timeoutMs` 15000.
- Narration: last 3 text blocks per run, 300 chars each.
- Memory: `agent-samples` keeps 50 entries; `steps` optional so old entries stay valid.
- Prompts in Spanish; code/comments in English; no line numbers in the repo.
- Checks before each commit (repo root): `claude plugin test plugins/tool-fold`, `claude plugin validate plugins/tool-fold`, `python3 scripts/validate.py`.

## Review Focus

1. `terminado: sí` with no calls since the last check → no advance (G1). Test in Task 1.
2. A step overrunning for 15 min: time left grows past `~1 min`, percent never drops, overdue checks ≤ 8. Test in Task 2.
3. A run stored with a v2 plan (`fired`, `fixed`, `replannedDone`, no `overdueChecks`) after the update: no crash, checks resume. Test in Task 2.
4. Old `agent-samples` entries without `steps`, and entries with malformed `steps`, still load (malformed `steps` dropped, entry kept). Test in Task 2.
5. Main-loop text (no `agentId`) and text of an unknown agent never reach `said`. Test in Task 2.

### Task 1: Pure plan logic and prompts (`plan.tsx`)

**Files:** Modify `plugins/tool-fold/hooks/plan.tsx`; Test `plugins/tool-fold/tests/plan.test.tsx`

**Interfaces — Produces:**
- `PlanStep = { title: string; estMs: number; realMs?: number; criterion?: string }` (`fixed` removed).
- `PlanState`: remove `fired`, `replannedDone`; add `overdueChecks?: number` (absent = 0). Keep `stepEstMs` (shown to Haiku as planned).
- `parsePlan(reply): { title: string; minutes: number; criterion?: string }[] | undefined` — accepts `N. t — M min` and `N. t — M min — listo cuando: c` (criterion ≤ 100 chars, cut).
- `parseReplan(reply, from, max)` — same item type and suffix; `ninguno` → `[]`; start at `from` or 1.
- `parseVerdict(text: string): { done?: boolean; evidence?: string }` — keys `evidencia:` and `terminado:` over the first 4 non-empty lines, any order, bold ignored; `sí|si|yes` → true, `no` → false.
- `overdueGapMs(checks: number): number`.
- `nextPlanCheck(plan, elapsedMs, now): { kind: 'overdue' | 'event' | 'ceiling' } | undefined` — none when every step is done; `overdue` when `elapsed ≥ stepEndAt + OVERDUE_GRACE_MS` and `now − askedAt ≥ overdueGapMs(overdueChecks)`; otherwise none within 60 s of `askedAt`; `event` when `hintAt > askedAt`; `ceiling` when `now − askedAt ≥ 5 min`.
- `growOverdue(plan, elapsedMs): PlanState` — new `stepEndAt`/`stepEstMs` per Global Constraints, `overdueChecks + 1`, `anchor = planBar(plan, elapsedMs)`.
- `applyDone(plan, elapsedMs, now, historyGrew): PlanState | undefined` — undefined without `historyGrew` or when all done; else `applyCount(plan, plan.done + 1, …)` with `overdueChecks: 0`, `hintAt: now` (a fast next step gets a check after the gap).
- `applyCount` unchanged except the factor clamp (1 to 3) and no `fixed` path (`scaledMs` removed; `restMs` = pending `estMs` sum × factor).
- `applyReplan(plan, steps, elapsedMs): PlanState` — `[]` or no pending steps → same object; new minutes scaled to the old pending `estMs` sum (unscaled), `criterion` kept, total ≤ `MAX_TOTAL_STEPS`, `anchor = planBar(plan, elapsedMs)`.
- `shouldReplan(plan: PlanState, advanced: boolean): boolean` — `advanced && plan.done + 1 < plan.steps.length`.
- `askDone($, ask: { mission; plan; elapsedMs; activity; calls; said?: string; thinking?: string; id }): Promise<{ done?: boolean; evidence?: string } | undefined>` replaces `askStepCheck`; prompt per spec § Design 4 (no `<paso_anterior>`, no calendar), examples for `sí` and `no`.
- `askPlan` asks for criteria; `similar` items may carry `steps` (Task 2 type) and are shown as `(pasos reales: Leer 2 · …)`.
- `askReplan` asks for criteria, says minutes are a split.
- `stepTimes(plan: PlanState, endElapsedMs: number): { title: string; estMs: number; ms: number }[]` — finished steps with `realMs`, the current one ending at `endElapsedMs`; unstarted ones left out.
- Removed: `parseStepReply`, `applyStep`, `applyLeft`, `applyOverdue`, `scaledMs`, `CHECK_FRACTIONS`, `askStepCheck`.

- [ ] **Step 1: Failing tests:** `parsePlan` with and without criteria; `parseVerdict` (`**terminado:** Sí`, evidence after verdict, garbage → `{}`); `nextPlanCheck` kinds and gaps (overdue backoff 30/60/120/240 s; event needs 60 s; ceiling 5 min; none when all done); `growOverdue` (end = elapsed + max(1 min, half the time in step), percent not lower); `applyDone` (G1, one step only, hint set, `overdueChecks` reset); factor 0.5 real/est → factor 1 (rest not shortened); `applyReplan` (sum preserved, criteria kept, `[]` and last-step cases return same object); `shouldReplan`; `stepTimes`; `askDone` prompt has no `<paso_anterior>` and has `<dice_el_agente>` when given, `maxTokens` 120.
- [ ] **Step 2:** Run → FAIL. **Step 3:** Implement; rewrite the v2 tests that assert removed behaviour into their v3 counterparts (list each). **Step 4:** Tests pass. **Step 5:** Commit `feat(tool-fold): plan v3 logic — yes/no step checks, code-owned time`.
