# Offload tables from a session start hook: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task, with the Plan loop of the owner's routing rules (`agent-skills:implementer` per task, `agent-skills:skeptical-reviewer` after each task commit). Steps use checkbox (`- [ ]`) syntax for tracking.

Status: done, merged with pull request #196 and released on 2026-11-26 in `agent-skills` 1.2.0 and `memory` 0.15.0 · Branch: `feat/offload-policy-hook` · Base: `dev`; rebase onto `dev` after `fix/prompt-review-2026-11-26` merges, before Task 5, because that branch changes the policy text and holds its latest measurement · Date: 2026-11-26 · Backlog item 4d

**Goal:** A user who installs `agent-skills` or `memory` gets that plugin's offload table at session start with nothing to paste or keep up to date; a plugin option turns it off for users who keep the table in their own instructions file.

**Architecture:** Each plugin ships a `SessionStart` hook that prints its offload table as plain standard output, which Claude Code adds to the context. The table text stays in its single source (`user-config/offload-policy.md` for `agent-skills`, `plugins/memory/user-config/offload-policy.md` for `memory`); `scripts/port.py` generates the copy that `agent-skills` needs inside its plugin folder, because an installed hook reads only files under its plugin root. A boolean plugin option, on by default, switches the hook off. The routing text (`user-config/routing.md`) stays pasted.

**Tech Stack:** Bash hook scripts, `hooks/hooks.json`, `userConfig` in `.claude-plugin/plugin.json`, `scripts/port.py`, `scripts/validate.py`, `claude plugin eval`.

**Spec:** this file's § Decisions, [ADR 0021](../../adr/0021-user-config-is-the-single-source-of-user-level-rules.md) (single source of user-level rules), [ADR 0012](../../adr/0012-ui-verifier-worker.md) (the offload table has one copy), backlog item 4d (owner: plan it, 2026-11-25; build it with a switch, 2026-11-26).

## Global Constraints

- One source per table. The copy inside `plugins/agent-skills/hooks/` is generated by `scripts/port.py` and checked by `port.py --check`; nobody edits it. `memory` reads its own `user-config/offload-policy.md` in place.
- A hook is silent and exits 0 whatever happens (missing file, unreadable folder): a failing hook disturbs every session.
- Off means off: with the option `false` the hook prints nothing.
- The pasted path keeps working: `user-config/offload-policy.md`, its ports and the README block stay where they are (`PUBLIC_PATHS`, ADR 0026), because Copilot and Codex users and users who turn the option off still paste it.
- No change to the text of either table: this plan changes how the table is delivered, not what it says.
- Vocabulary, changelog, generated files and commit checks follow the repository `CLAUDE.md`. Shell only: the only existing Python file touched is `scripts/port.py`, which Task 0 first makes clean under ADR 0031; `scripts/validate.py`, `scripts/tests/test_port.py` and `plugins/memory/evals/*.py` are not touched. New tests go into new files, which are clean from the start.
- Measured before merging to `dev` (N6): Task 5. The description of no skill or agent changes.

## Decisions

| Decision | Reason | Alternative rejected |
|---|---|---|
| On by default (`"default": true`; the hook is off only for the exact value `false`) | The aim is that nobody maintains a pasted table; a default of off would reach no new user | Off by default: safe for current users, no gain for new ones |
| Skip when the user's instructions file already holds the table: the hook looks for the line `## Offload policy (main conversation only)` (for `memory`: `### Offload policy: memory plugin (main conversation only)`) in `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/CLAUDE.md` and prints nothing when it is there | Every current user pasted the table; after the update they would load it twice until they act. One `grep` removes that migration step | Option only: a double load for every current user until they read the changelog |
| Matcher `startup\|clear\|compact`, as `memory` uses | A resumed session keeps its transcript, which already holds the text; a compaction may drop it | All sources: a second copy on every resume |
| Inside an eval the hook is silent unless the case asks for it: silent when `CLAUDE_CODE_EVAL_CONFINED` is set and `EVAL_OFFLOAD_HOOK` is not exactly `on`. Six new `offload-*-with-hook` cases set `execution.env: {EVAL_OFFLOAD_HOOK: "on"}` and carry no `append_system_prompt` | 32 of the 42 cases have no `case.yaml` and cannot set a variable, so an opt-out per case cannot cover them; every recorded trigger and `neg-*` result would change arm. With the hook silent by default in an eval, no existing case changes and no record moves. The existing `with-policy` cases keep measuring the pasted path | An opt-out line in every case, enforced by `validate.py`: impossible for prompt-only cases, and it touches `validate.py` (31 findings to clean first) |
| The eval marker is not documented, so a canary guards it: Task 5 step 1, and the Eval protocol says to repeat it before any policy measurement | If the harness drops the variable, every case would silently measure with the table | Trusting the variable |
| The `memory` trial harnesses are left as they are | They run with the user's real home: on a machine with the table pasted the skip check keeps them as before; on a machine without it they gain the table, which is what that user's sessions now have | Editing `trial_env.py`: a Python file to clean for no measured need |
| Routing stays pasted | 8,626 bytes is close to the 10,000-character cap and no eval embeds it; revisit after this ships | Both in one hook |
| `scripts/cloud-setup.sh` step 3b stays as it is; the script also writes `pluginConfigs` → `agent-skills@mili-ssm` → `options.offload_policy: false` into the user `settings.json` (its existing embedded Python step style), unless `AGENT_SKILLS_OFFLOAD_HOOK=1`. It installs only `agent-skills`, so `memory` needs nothing there | The owner's cloud account preferences already carry the table, which a hook cannot see, so a hook on by default would load it twice there. A cloud snapshot older than the release keeps the old script for up to about 7 days: two copies (about 700 tokens) until it reruns, accepted and named in the ADR | Shipping the default as `false` first: no gain for new users |
| Blind spots of the skip check are documented, not solved: a table brought in by an `@import`, a project `CLAUDE.md`, `CLAUDE.local.md`, account preferences, or a file with CRLF line ends is not seen, so the table loads twice until the user turns the option off; a stale pasted copy wins over the plugin's until the user deletes it | Each costs about 700 tokens, and the option is the remedy | Parsing imports and every instruction file in a hook |
| New ADR 0032, `Amends 0021` and `0012` | The delivery of a user-level rule changes; the single source does not | A review section in 0021: an amendment of a Decision needs its own record |

## Kill criteria

- Task 5 canary: the bare case shows the table, or the with-hook case does not (for example `CLAUDE_CODE_EVAL_CONFINED` is absent under `--scaffold`): stop and do not measure; re-plan the switch.
- Task 0 changes behavior (`port.py --check` or `scripts/tests` differ) or cannot reach the gate without a suppression: stop and take it to the owner.
- Task 5: a `-with-hook` case scores 2 or more of 6 below its `-with-policy` twin: the default becomes `false` for that plugin and the ADR records it; the hook still ships as an opt-in.

## Review Focus

1. A hook that prints a partial table (file cut, `head` misuse): the test compares the output byte for byte with the source file.
2. The skip check matching a mention of the heading inside a code block or quote of the user's file: accepted (the user then has the text); the test pins the exact line match (`grep -qxF`).
3. `CLAUDE_CONFIG_DIR` unset and `HOME` unset: the hook still prints the table and exits 0.
4. `CLAUDE_CODE_EVAL_CONFINED` set with `EVAL_OFFLOAD_HOOK` unset, `off` or any other value: silent; only the exact value `on` prints.
5. The generated copy drifting: `port.py --check` fails when the copy differs from the source.
