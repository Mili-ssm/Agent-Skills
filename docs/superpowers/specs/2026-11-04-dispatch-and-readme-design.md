# Proactive dispatch wording + README install and recommended prompt

Status: proposed · Date: 2026-11-04

## Intent
1. Raise the chance that the main model dispatches `skeptical-reviewer` on its own (measured 0/3 with a Sonnet main, policy only). Owner: refine prompts, no hooks; in real use `implementer` already fires constantly because the owner's main model rarely writes code.
2. README: install guides for Claude, Copilot and Codex in collapsible sections, then a recommended prompt for other users covering only how to use the agents and skills (not the owner's whole working agreement).

## Goals · non-goals · anti-goals
- Goals: `offload-skeptical-reviewer-with-policy` dispatch up from 0/3; no regression elsewhere; one home per fact in the README.
- Non-goals: hooks (owner declined); changing other workers' wording.
- Anti-goals: the reviewer dispatched after trivial edits (`neg-*` must stay silent); a README prompt that drifts from `user-config/`.

## Approaches
| | Approach | Trade-off |
|---|---|---|
| **A (picked)** | Anchor the reviewer rule to a moment: "before your final answer, if you or a worker changed ≥ 2 files or ≥ 20 lines in this task, dispatch `skeptical-reviewer` and wait for its report", same words in the policy row and the description | Turns an additive "after X, also Y" into a definition-of-done gate in text; still probabilistic |
| B | Plugin hooks (Stop block / PostToolUse context) | Near-deterministic; owner declined |
| C | Description wording only | Cheapest; policy rows were what moved other workers (ADR 0010) |

## Design
- Dispatch: prompt-engineer drafts the policy row and description wording for A; measured with `offload-skeptical-reviewer-with-policy` (and `-quality`) at 3 runs vs the baseline, plus every `neg-*` (description change, eval protocol).
- README Install: three `<details>` blocks (Claude Code, GitHub Copilot CLI, OpenAI Codex). Copilot and Codex steps move from `docs/ports.md` to the README; `docs/ports.md` keeps mapping and limits and links to the README for install.
- README "Recommended prompt": generated by `scripts/port.py` between markers from per-tool sources, one `<details>` per tool: the offload table (`user-config/offload-policy{,.copilot,.codex}.md`) plus a new skills/agents routing table (source `user-config/routing.md`, ported to tool names like the policy). `port.py --check` fails when the README block is stale.
- The routing table is the generic form of the owner's "Skills, agents and commands" section: need → skill/agent/command, no personal rules.

## Evidence
Docs: "use proactively" encourages but does not guarantee delegation; only @-mention guarantees (code.claude.com/docs/en/subagents). ADR 0010/0012: substitution rules fire 3/3–6/6; additive or "do it yourself" ones 0/3 with Sonnet.
