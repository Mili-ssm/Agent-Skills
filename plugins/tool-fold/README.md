# tool-fold

Opt-in mod of the [`mili-ssm` marketplace](../../README.md), installed apart from `agent-skills` (ADR 0011). It makes offloading to Haiku/Sonnet visible (ADR 0010) and keeps tool output out of the way until asked for.

## What it shows

- Tools, skills and agents in the chat: each call one line (`▸ ● Bash Run the e2e suite`; skills by name), a run of them one group line (`▸ ● qa-review · implementer · Bash  <Haiku summary>`).
- Running agents live only in an "Agentes" pane (beside the chat, or above the prompt in a narrow VS Code panel; `/agents-dock` reopens it): mission, model, task progress or a Haiku `≈%` estimate (after any call, at most every 30 s), as one borderless card each: line 1 an icon by type (`◆` main agent, `⌕` read/explore, `✎` writers, `▶` runners, `◇` other), the bold name, the model (its `●` colored by family: opus purple, sonnet blue, haiku teal, fable gold, other dim) with the elapsed time dim after it (`● opus-5-5 · 1m 12s`) and, at the right, the key datum (`≈60% · ~3 min` or `3/7`; empty with no estimate); line 2 a thin progress line (an Svg like plan-progress's, a glyph line on the terminal; none without an estimate); line 3 one dim line with the live call (the model's own description, else Haiku's) or the mission. A subagent parked on its background process swaps its type icon for `◷`. Colors follow the state: running orange, waiting blue, completed green, failed or stopped red.
- When one ends it leaves the pane, its chat row shows the folded card and one dim line at the bottom of the chat says it ended (`✓ implementer · sonnet-5-5 · 8m 51s · … · 26 calls · 26 commands`).
- On Desktop and VS Code running agents draw as cards in the band above the prompt, and no pane opens on its own (Desktop does not tell the mod when its docked pane is closed; VS Code's pane title bar cannot be removed). Where the pane is placed on VS Code (`/agents-dock`) the band yields. The cards were not yet seen drawing there (open, [`docs/mods-surfaces.md`](../../docs/mods-surfaces.md)). `/agents-dock` still opens it beside the chat. `/agents-debug` reports what the band and the pane see
- The main agent's wait is one card for all its waits (detail `bash · en segundo plano` (the label stays in the mission, never repeated), `esperando a check-runner · bash en segundo plano`, `a 2 agentes`, `2 procesos en segundo plano`; plugin prefixes stripped; elapsed since the earliest wait; estimate, progress and icon from the process whose estimated end is latest, none when only agents are waited on). Where the "Agentes" pane is up (not on Desktop, which never reports its close) the band draws no cards, and the pane title counts the cards it shows. While it waits on background work, idle or not (a `Bash` that answered a `backgroundTaskId`, a `Monitor`, a background agent), the "Agentes" pane and the Desktop band list it first, ahead of every other agent, as `◆ Claude · esperando` (bold, blue; `Claude · en segundo plano` while a main turn runs, same card and place), the main model, what it waits on as the mission, and, at the right `≈%` (elapsed over the estimate, held at 99% until done, then `≈99% · más de lo previsto` (only 15 s after the estimate; within that grace it keeps the % and the time left) in place of the time left; never while it waits on an agent, whose own card carries it). What it waits on reads as the call's `description`, else, once at launch, Haiku's plain phrase of at most 8 words (Spanish) for the command. The estimate: at launch (a wait, main's or a subagent's, and an agent's spawn) one Haiku call receives the text (description, command or brief, and a stated duration if one parses) together with the similar past runs (up to five by word overlap, with their durations, or `none`) and answers `minutos: N`, read strictly; its answer is the estimate. Until it answers the card shows the best deterministic value: a stated duration (`sleep 290`, "Wait 5 minutes", "2–3 horas" → midpoint, read without a model), else the median of similar finished runs (the last 50 `{ summary, durationMs, at }` kept across sessions in `$.store`; similar from a word overlap (Jaccard over words of 3+ letters, stopwords out) of 0.5), else none. The icon, one dim character before the right datum, says what Haiku saw: `✦` a stated duration, `⟲` similar runs, `?` neither. Claude's own last message overrides it when it states a duration ("unas 2–3 horas" → 150 min), read once by Haiku when the turn ends and applied to the waits that turn started, `✦`. When the elapsed time passes the estimate, a clock tick asks Haiku again with the elapsed time and the previous estimate for a new total (`minutos: N`, longer than the elapsed time), at most once per wait every 30 s; never from a draw. A subagent's card waiting on its process uses that process's estimate, and an agent that ends its turn with open waits records no sample. Each wait costs one estimate call (plus one for a missing label), and one per turn end. With no estimate the card draws the empty track only. Every card with a `≈%` of more than 5% adds the time left (elapsed × (1 − p) / p): `≈60% · ~3 min`, `<1 min`, `~1 h 5 min`. It goes when the last wait's notification says it ended (an agent that ends well or a wait that `completed` lingers 5 s in green at `100%`, a failed one goes at once); a new turn only switches the label. A background agent stays running (and waited on) through turns where the engine lists it `waiting` on its own work, and its own background command counts as its wait even when the Bash result says it ends with the final response; `/agents-debug` lists each run's id, status and background flag. While a main turn runs with no background work the same card reads `◆ Claude · trabajando` in orange: elapsed since the prompt, the progress line and `≈% · time left` from one Haiku call at turn start (the prompt plus similar past turns, `turn-samples` in `$.store`, turns of 20 s or more), the latest main-loop call (else the prompt) as detail. Background work turns it blue as above; a turn that ends with none lingers 5 s green at `100%`, then the card goes (none while idle). The main card is drawn first in its own group, then a dim `── Agentes N ───` line (count right after the word), then the subagents' cards, in the pane and the band; the pane title (`Agentes · N`) counts subagents only.

A subagent's background shell (an owned wait) ends when the subagent, parked on it (`backgroundWakesOwner`), is woken: the message that starts its turn names the task (`<task-id>`); a shell that dies with the subagent's final response (`backgroundEndsWithFinalResponse`) makes no wait. Safety net, for an owned wait whose agent has ended, with no sample recorded: the main loop gets a notification naming it; or it outlives max(2 × estimate, estimate + 10 min). (A rule that dropped it when a main turn ended after the agent completed was removed: a subagent completing while its command runs is the normal case.) Finished runs under 20 s teach nothing. Unverified against a live session: how the woken turn's text is framed. Unverified against a live session: the notification's `<task-id>`/`<status>` tags are read from its text (open, [`docs/mods-surfaces.md`](../../docs/mods-surfaces.md)).

## Install

```bash
claude plugin install tool-fold --marketplace Mili-ssm/Agent-Skills
```

In a cloud environment, list it in `AGENT_SKILLS_MODS` (for example `AGENT_SKILLS_MODS="tool-fold"`): [`scripts/cloud-setup.sh`](../../scripts/cloud-setup.sh) installs the mods named there. Update it like the other plugins ([Update](../../README.md#update)).

The mod hooks API is early access and may change between Claude Code releases; a failing hook is skipped and never blocks a session (ADR 0011).
