# tool-fold

Opt-in mod of the [`mili-ssm` marketplace](../../README.md), installed apart from `agent-skills` (ADR 0011). It makes offloading to Haiku/Sonnet visible (ADR 0010) and keeps tool output out of the way until asked for.

## What it shows

- Tools, skills and agents in the chat: each call one line (`▸ ● Bash Run the e2e suite`; skills by name), a run of them one group line (`▸ ● qa-review · implementer · Bash  <Haiku summary>`).
- Running agents live only in an "Agentes" pane (beside the chat, or above the prompt in a narrow VS Code panel; `/agents-dock` reopens it): mission, model, task progress or a Haiku `≈%` estimate (after any call, at most every 30 s), as one borderless card each: line 1 an icon by type (`◆` main agent, `⌕` read/explore, `✎` writers, `▶` runners, `◇` other), the bold name, the model (its `●` colored by family: opus purple, sonnet blue, haiku teal, fable gold, other dim) with the elapsed time dim after it (`● opus-5-5 · 1m 12s`) and, at the right, the key datum (`≈60% · ~3 min` or `3/7`; empty with no estimate); line 2 a thin progress line (an Svg like plan-progress's, a glyph line on the terminal; none without an estimate); line 3 one dim line with the live call (the model's own description, else Haiku's) or the mission. A subagent parked on its background process swaps its type icon for `◷`. Colors follow the state: running orange, waiting blue, completed green, failed or stopped red.
- When one ends it leaves the pane, its chat row shows the folded card and one dim line at the bottom of the chat says it ended (`✓ implementer · sonnet-5-5 · 8m 51s · … · 26 calls · 26 commands`).
- On Desktop and VS Code running agents draw as cards in the band above the prompt, and no pane opens on its own (Desktop does not tell the mod when its docked pane is closed; VS Code's pane title bar cannot be removed). Where the pane is placed on VS Code (`/agents-dock`) the band yields. The cards were not yet seen drawing there (open, [`docs/mods-surfaces.md`](../../docs/mods-surfaces.md)). `/agents-dock` still opens it beside the chat. `/agents-debug` reports what the band and the pane see
- The main agent's wait is one card for all its waits (detail `bash · en segundo plano` (the label stays in the mission, never repeated), `esperando a check-runner · bash en segundo plano`, `a 2 agentes`, `2 procesos en segundo plano`; plugin prefixes stripped; elapsed since the earliest wait; estimate, progress and icon from the process whose estimated end is latest, none when only agents are waited on). Where the "Agentes" pane is up (not on Desktop, which never reports its close) the band draws no cards, and the pane title counts the cards it shows. While it waits on background work, idle or not (a `Bash` that answered a `backgroundTaskId`, a `Monitor`, a background agent), the "Agentes" pane and the Desktop band list it first, ahead of every other agent, as `◆ Claude · esperando` (bold, blue; `Claude · en segundo plano` while a main turn runs, same card and place), the main model, what it waits on as the mission, and, at the right `≈%` (elapsed over the estimate, held at 99% until done, then `≈99% · más de lo previsto` (only 15 s after the estimate; within that grace it keeps the % and the time left) in place of the time left; never while it waits on an agent, whose own card carries it). What it waits on reads as the call's `description`, else, once at launch, Haiku's plain phrase of at most 8 words (Spanish) for the command. The estimate: at launch (a wait, main's or a subagent's, and an agent's spawn) one Haiku call receives the text (description, command or brief, and a stated duration if one parses) together with the similar past runs (up to five by word overlap, with their durations, or `none`) and answers `minutos: N`, read strictly; its answer is the estimate. Until it answers the card shows the best deterministic value: a stated duration (`sleep 290`, "Wait 5 minutes", "2–3 horas" → midpoint, read without a model), else the median of similar finished runs (the last 50 `{ summary, durationMs, at }` kept across sessions in `$.store`; similar from a word overlap (Jaccard over words of 3+ letters, stopwords out) of 0.5), else none. The icon, one dim character before the right datum, says what Haiku saw: `✦` a stated duration, `⟲` similar runs, `?` neither. Claude's own last message overrides it when it states a duration ("unas 2–3 horas" → 150 min), read once by Haiku when the turn ends and applied to the waits that turn started, `✦`. Re-estimates ask Haiku for the minutes that REMAIN (`minutos: N`) and the total is elapsed + remaining, from the clock tick (never a draw), at most every 30 s per item: at 50% and 80% of the current estimate and every tenth of it (5 to 20 min) after that (not for a stated or message estimate), and, once past the estimate, in an overdue wording (answers there only lengthen). An agent's ask also sees its task list and recent calls, and a percent only when it is real (task list or Haiku's `≈%`); a wait's ask never gets one, only the elapsed time. A progress answer counts only if it differs 20% or more from the current total, blended 50/50 with it. The percent never goes down when an estimate changes (it runs from the percent shown then to 99% at the new end); an answer older than the latest ask is dropped; `/agents-debug` lists variant, Haiku's remaining and the total. A subagent's card waiting on its process uses that process's estimate, and an agent that ends its turn with open waits records no sample. Each wait costs one estimate call (plus one for a missing label), and one per turn end. With no estimate the card draws the empty track only. Every card with a `≈%` of more than 5% adds the time left (elapsed × (1 − p) / p): `≈60% · ~3 min`, `<1 min`, `~1 h 5 min`. It goes when the last wait's notification says it ended (an agent that ends well or a wait that `completed` lingers 5 s in green at `100%`, a failed one goes at once); a new turn only switches the label. A background agent stays running (and waited on) through turns where the engine lists it `waiting` on its own work, and its own background command counts as its wait even when the Bash result says it ends with the final response; `/agents-debug` lists each run's id, status and background flag. The main card is the whole request's card (it absorbed `usage-band`, ADR 0016): the header time runs from the owner's prompt across turns and waits and stops when Claude is idle (nothing open, no agent working). `◆ Claude · trabajando` (orange, no estimate, empty track) while it works, blue as above with background work, and `◆ Claude · listo` (grey line, `✓`) once idle, **kept until the owner's next prompt**. Line 3 is Haiku's phrase for what Claude does (`▸ Revisando los hooks`, at most one call every 30 s after new calls; the latest call's label or the prompt until the first lands, the process label while waiting) and, once done, the conclusion of the last answer (`✓ …`, one call per idle moment); a miss leaves the previous text. Line 4: `◔ 13%    10 calls · 2 skills · ●● 3 agents          Σ 28m 03s · 7.0M` (context share first, its icon filling by quarters and colored softly green `#5f9e6e` under 50% used, amber `#c49a3c` to 80%, red `#c0605a` above, then a gap and the dim counts of the whole request, one dot per model family the agents used; the session's busy time and tokens, from the second second on, right-aligned by a `flexGrow` spacer; the terminal keeps the order on one line with spaces). No model call is a turn sample. The main card is drawn first in its own group, then a dim `── Agentes N ───` line (count right after the word), then the subagents' cards, in the pane and the band; the pane title (`Agentes · N`) counts subagents only.

A subagent's background shell (an owned wait) ends when the subagent, parked on it (`backgroundWakesOwner`), is woken: the message that starts its turn names the task (`<task-id>`); a shell that dies with the subagent's final response (`backgroundEndsWithFinalResponse`) makes no wait. Safety net, for an owned wait whose agent has ended, with no sample recorded: the main loop gets a notification naming it; or it outlives max(2 × estimate, estimate + 10 min). (A rule that dropped it when a main turn ended after the agent completed was removed: a subagent completing while its command runs is the normal case.) Finished runs under 20 s teach nothing. Unverified against a live session: how the woken turn's text is framed. Unverified against a live session: the notification's `<task-id>`/`<status>` tags are read from its text (open, [`docs/mods-surfaces.md`](../../docs/mods-surfaces.md)).

Long agents show steps instead of a percent (`hooks/plan.tsx`, switched by `PLAN_ENABLED`; deleting the file and its call sites removes it). When an agent's first estimate is over `PLAN_MIN_MS` (5 min) one Haiku call splits the work into 3 to 6 steps with minutes (strict `N. <title> — M min` lines, else no plan and the usual `≈%` card), and the card reads `<current step, dim, at most 26 chars> 40% · ~8 min` (`99% · finalizando` once all are done while it runs): no `X/Y` count, the percent is the whole run's, the same value the bar draws. The bar is step time over plan time and never goes back. At 50%, 80% and 95% of the current step's estimate (1 min apart at least, 5 min at most), and on the next tick after a call whose words match a later step's title better than the current one's, Haiku is asked, in one call with an activity summary (reads, edits, creations, commands, tests since the start and since the step began) and the last 8 calls, the current step and the minutes left in it (`paso: N`, `falta: M`; the calendar is labelled reference only). The step advances at most one per check and only if calls were added since the last check; `falta` is clamped (0.5 min to 3x the step), blended 50/50 with the previous value and shortens at most 30% per check, and the count never goes back; a finished step fixes its real time and the steps still to run are scaled by real over estimated time (0.5 to 3). A step 15 s past its estimate is checked the same way (no 99% check: that overdue check is the "reached 100%" one). Right after an applied check, a second and separate Haiku call (`askReplan`, 250 tokens, 15 s) rewrites only the steps after the current one when the step advanced, when the check was an overdue one, or when it was the 95% one; 50% / 80% checks and hints after the 95% one never replan, a stuck step is replanned once per step (not at every overdue check), and at most one replan is in flight per run. It receives the mission, the steps done with planned and real minutes, the current step, the pending steps (reference only) and the run's last 40 calls (`<historial>`), and answers `N. <title> — M min` lines numbered after the current step (a list restarted at 1 is renumbered) or `ninguno` (believed only when at most one step was pending; new steps offered when none was pending are ignored, since there is no rest to clamp them against). A step advance that lands while a replan is in flight gets one more replan once it ends. The result has at most 8 steps in total; its minutes are scaled to 0.5 to 2 times the old rest, marked `fixed` (the real-over-estimated factor does not scale them again) and applied only if no later check moved the plan since it was asked; the percent does not go back. Anything else keeps the plan; `/agents-debug` logs `plan replan ok|failed`. Cost: up to 3 checks per step plus 1 to 2 replans, Haiku only; `REPLAN_ENABLED` (`plan.tsx`) turns off the replan alone. The agent's own task list wins over the plan, and waits and the Claude card never get one. `/agents-debug` logs each plan build and check. Words are matched only on Spanish natural text (a Bash call's description or Haiku's phrase for the command, cached by command text and retried once after ~5 s; if both fail the check is hinted directly, and other tools never hint); `/agents-debug` adds `translations: ok= retried= failed= cached=`. Haiku's phrase states the command's effect (not the wrapper); a command that runs an interpreter on an inline body (heredoc, `-c`, `-e`) shows `Script: <phrase>` (the tag is display only, the plan matches the bare phrase), one that runs a script file shows `Ejecuta <file>` with no Haiku call, and a command over 1500 chars is sent as its first 1000 and last 450. A running agent with no call in progress 10 s after its last call ended shows `◐ pensando… 1m 20s` instead of that call; once per such episode a planned run asks the step count on the next tick, and the check's `<progreso>` ends with `Ahora: pensando desde hace 1m 20s (sin herramientas)`.

## Limits and open ideas

| Observed | Why | Options (not implemented) |
|---|---|---|
| Sibling agents launched together with near-identical briefs (e.g. 5 issue reviewers, 2026-11-03) get slightly different plans: 4 vs 5 steps, different titles and minutes | Each spawn makes its own Haiku plan call; `$.model.complete` takes no temperature, so wording varies run to run | (a) reuse the plan of a sibling spawned within ~1 min whose brief overlaps ≥ 0.6 (Jaccard), rescaled to its own estimate; (b) cache plans by brief summary across sessions, like `agent-samples`; (c) a fixed skeleton per agent type (read · do · verify · report) with Haiku only filling titles and minutes |
| Similarity (similar runs, plan hints, sibling plans) is word overlap (Jaccard): "reescribe" ≠ "Escribir", "tests" ≠ "pruebas", Spanish vs English labels miss | Cheapest deterministic measure; the mod API (`claude-code.d.ts`, 2026-11) has `$.model.complete` and `$.model.classify` but no embeddings; hooks have no `WebAssembly` (by design), so transformers.js/ONNX cannot run inside the mod | (d) local embeddings in a child process (`$.process.spawn`, the API's route for compiled code): a small Node script with transformers.js + a multilingual model (e.g. multilingual-e5-small) or Ollama, kept alive for the session and fed over stdin — no data leaves the machine, but it needs Node/Ollama on the host, a one-time model download and a warm-up; or an external embedding API via `$.http.fetch` (Anthropic has none; e.g. Voyage), which needs a key and sends task text out; (e) Haiku as judge only on the top ~5 lexical candidates (`$.model.classify`), one call per lookup; (f) cheap lexical upgrades first: accent folding, Spanish/English stemming, a small synonym table (tests↔pruebas, leer↔read) |

Variation between siblings with different scopes (different issue sets) is expected and not a defect; the open question is only whether same-scope siblings should share one plan. Trade-off: (a) and (b) save calls and make cards comparable, but a shared plan hides real differences between briefs.

## Install

```bash
claude plugin install tool-fold --marketplace Mili-ssm/Agent-Skills
```

In a cloud environment, list it in `AGENT_SKILLS_MODS` (for example `AGENT_SKILLS_MODS="tool-fold"`): [`scripts/cloud-setup.sh`](../../scripts/cloud-setup.sh) installs the mods named there. Update it like the other plugins ([Update](../../README.md#update)).

The mod hooks API is early access and may change between Claude Code releases; a failing hook is skipped and never blocks a session (ADR 0011).
